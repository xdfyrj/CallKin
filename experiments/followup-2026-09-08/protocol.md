# CallKin 후속 연구 규약 - 2026-09-08

제출 PDF와 분리한 새 연구다. 기존 ripgrep-main, fd, zoxide는 모두 이미 결과를 본 개발 사례이며, 새로운 원본의 검증이나 외부 독립 재현이라고 부르지 않는다.

## 비교
기존 plain O3S의 전체 함수 대상과 사전 경계를 고정한다. 본문 Token+CFG의 교집합(body2)과 Token+CFG+Relation의 교집합(combined3)을 비교한다. k=16이 주 비교이고 8,32는 민감도 분석이다. 각 경로의 점수, 0점 제외, ID 동률 처리, 양방향 후보 합집합은 기존 코드를 재사용한다. 동일한 top32 순위의 접두부를 사용할 경우 직접 작은 k를 계산한 결과와 단위 검사로 대조한다.

combined3 후보는 body2 후보의 부분집합이다. 관계 조건으로 정답 후보 수가 늘 수는 없다. 정답 손실, 오병합 억제와 비용 감소를 함께 측정한다. 최종 복구 개선도 후보 제거에 따른 병합 순서 및 예산 효과일 수 있다. 관계 고유 정보의 우위를 주장하려면 이후 선택률을 맞춘 음성 대조가 필요하다.

Align, Decide와 complete-link는 변경하지 않는다. 구조 .95 이상, 관측 상수/데이터 채널1.0, 관측 채널 하나 이상, 불완전/불투명 간접 점프 보류를 유지한다. 각 구성에 독립적으로 비교10,000회, 정렬500,000,000칸을 적용하며 추가 교차 비교도 센다. 기존 전체 후보 큐 거부 정책을 유지한다. 예산을 넘는 실행은 미완료이며 품질0점으로 처리하지 않는다. 후보 비용부터 계산한다.

비교 기준선은 비어 있지 않은 정규화 명령 토큰의 정확 일치와 기존 out-in V0이다. 정확 일치에는 심볼이나 정답을 넣지 않으며, F6 슬롯 조건을 적용하지 않는 단순 기준선임을 명시한다. Rescue는 combined3의 k16에서만 별도 보조 결과로 기록한다.

## 정답 감사
48개 원본 그룹을 새 예측 전에 선택한다. 프로그램마다 다중 원소 그룹10개를 고정 seed의 SHA256 순위로 추출한다(총30). 목적 표본은 프로그램마다6개이며 공유주소, trait구현, closure, 생성코드/shim 후보, drop관련, 큰 그룹 순으로 고른다. 중복은 제외하며 해당 유형이 없으면 사전순 미선택 다중원소 그룹으로 대체하고 기록한다. 무작위 표본과 목적 표본 결과는 합쳐 오류율로 쓰지 않는다.

모든 구성원 주소와 심볼, 소스 파일/정의 위치, 버전과 체크섬, 판단 이유와 불확실성을 기록한다. 기존 양성/중립 규칙은 그대로 둔다. 소스와의 일치는 컴파일러 내부 원본ID의 확정이 아니다. LLM 에이전트의 소스 검토를 외부 사람의 독립 감사로 표현하지 않는다. 확인하지 못한 항목은 미확정으로 남긴다.

## 측정
예측 파일을 저장하고 해시를 고정한 다음 정답을 읽는다. 기존 linkage label_pair와 일치하는 TP/FP/FN/TN, P/R/F1, 원본별 비중립 정답 쌍 재현율의 평균, 양성 쌍이 있는 원본의 정확 집단 복구율을 보고한다. 정확 복구는 해당 원본의 대상 구성원 전체와 예측 집단이 같고 추가 구성원이 없는 경우이며 중립 쌍 채점보다 엄격한 보조 지표다.

관측 불충분, 검색/추가비교 미도달, 예산 보류, 구조 탈락, 슬롯 탈락, 병합 손실을 분리한다. 추가 교차 비교와 Rescue 때문에 단순 단조 깔때기가 아닐 수 있으므로 추가 복구를 별도로 기록하고 합계를 검산한다.

입력/코드 해시, Python 버전, 로드/검색/판정 시간과 프로세스 최대RSS를 남긴다. 구성 간 Align 캐시를 무료로 공유하지 않는다. 실행당12GiB RSS 또는30분에서 중단하고 자원 미완료로 기록한다. 최초 단계는 이 규약의 비교와 감사 기록을 남기는 것이다. 새 프로그램 검증, 외부 사람의 재현과 새 방법은 후속 단계이며 완료했다고 간주하지 않는다.
